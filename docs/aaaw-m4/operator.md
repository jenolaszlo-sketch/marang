# Operating the M4 repository-effect graph

Use the M4 runtime only with the existing bounded Windows M3 checkout profile. Prepare the immutable graph and intents, inspect the exact revision proposal and obtain approval before execution. A prepared graph is review material. Each fresh mutation still needs current Hufu authority; retained prerequisites obtain current authority again before a dependent write.

Read `RepositoryEffectGraphSupervisor.ReadAsync` with an authenticated operator. It shows the actual checkout separately from every effect's original receipt. Selected effects become accepted prerequisites only after local validation, compatible outputs and their own prerequisite chain are proven. A full workflow validation failure can coexist with successful local validation; review the failed goal evidence before authoring the next graph.

For a correction use `DrillDownAsync(workflowId, candidateRevisionId, actor)` after activation, or the ordinary M2 pending-proposal view before approval. Check the actual physical base, effects preserved for semantic use, historical effects retained only as physical base, replacements and invalidated descendants. In the canonical scenario R3 starts from S3 containing A/B/C and selects A/B2/C2. Approval never implies that B/C vanished from the checkout.

Use `ExplainEffectAsync` to inspect a particular effect's origin, prerequisites, patch and base identities, authority receipts, recorded post-state and validation. Physical classifications such as `AppliedThenAdvanced` retain historical truth; they do not authorize the effect under a later revision. Pending prerequisite names explain why a descendant cannot run. Historical prerequisite failures are contextual and do not block an otherwise coherent current graph.

After a host restart reopen the same journals and controlled checkout, restore registry definitions from immutable revision history, and dispatch the same effect identities through the graph runtime. Do not generate a replacement solely because a result receipt is absent. The writer reconciles exact state before any retry. A pending corrective proposal must resume with its original digest and obtain matching approval.

If an effect is partial or unresolved, stop mutation in this checkout. Catch-up names blocked descendants and retains the physical observations. There is no automatic replay, repair, block-clear or rollback operation. Preserve the checkout and journals for deliberate investigation; external edits are not evidence of safe recovery. Cancellation and supersession fence logical contribution while retaining existing files.

Run `eng/qualify-aaaw-m4.ps1 -ReuseQualifiedPackages` from a clean locally committed source tree to reproduce against the existing pinned package feed. Without that switch the existing M1 package qualification builds the locked producers first. Qualification checks that source stays unchanged, runs the complete consumer suite including earlier milestone probes, and captures only final-run M4 evidence. It does not publish packages or push branches. Native process-kill evidence qualifies Windows; other platforms and power loss need separate qualification.
