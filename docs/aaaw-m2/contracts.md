# Experimental supervisor continuity contracts

Initialize the M1 revision repository, delegation journal and authority owner, then `SqliteSupervisorContinuityStore`, `SupervisorCatchUp` and `DelegationRecoveryActions` against the same `IZhinuSqliteDatabase`. All mutation APIs are trusted-host seams. Authenticate the actor outside model/tool payloads and admit a finite read/report authority profile and execution ports. The qualification console's fixed operator is a fixture, not production authentication.

`RecordIntentAsync` records the actual authored goal, trigger, rationale and bounded evidence references for one exact historical revision or pending candidate. The Fuwen objective must match. Record intent and `CaptureProposalContextAsync` before approval/commit. A crash between proposal creation and host metadata recording leaves an exact pending proposal and a visibly incomplete context; repeat the host metadata step before continuing. M1 archives contain objective hashes, so migration cannot invent the original goal from those bytes.

`BeginDiscussionAsync` retains the pending question, missing information, affected logical work, offered options and references. `ResolveDiscussionAsync` requires the original decision ID, offered choice and current state digest. Progress or another revision invalidates that decision. `DismissDiscussionAsync` explicitly closes a pending discussion, including stale discussions, without applying its choice; open a new discussion from fresh state. None of these calls commits a revision.

`SupervisorCatchUp.ReadAsync` returns current intent, selected branches, current authoritative results, superseded prior execution/results, pending decisions, current and historical provider conditions, blockers, recent changes and recent revision detail. A completed provider task by itself is not an authoritative workflow result: the active manifest must select a completed accepted execution. A cancelled workflow has no current result authority. The latest 16 revisions and 32 meaningful changes are presented; counts report omitted history, and `DrillDownAsync` inspects any retained revision.

The derived supervisor states are Running, Discussing, AwaitingApproval, ReadyToApply, DelegationUnresolved, Blocked, Completed and Cancelled. ReadyToApply describes durable approval, not permanent permission; commit re-evaluates Hufu. Stale proposals, expired approvals and denied operations remain explicit decisions. A checkpoint is actor-scoped and can acknowledge only the exact observed revision/watermark; it has no effect on correctness or execution.

`DelegationRecoveryActions.Project` distinguishes reconnectable, complete, failed, known non-reconnectable, unknown and known unsafe-to-retry operations. The projection is a review token, not authority. Every action reconstructs its classification and validates immutable execution-to-delegation binding and journal/state digests. The provider's internal run ID is not assumed equal to the manifest run ID.

Wait leaves the condition pending. Observe only addresses a captured known operation and never calls Start. Errors remain explicit observation outcomes; a hard interruption retains the choice for fresh safe observation. Replacement is available only under the finite read/report policy. `PrepareReplacementAsync` rejects a candidate that preserves the old operation, then links a durable recovery decision to the exact M1 proposal. `ApproveReplacementAsync` records exact authenticated approval. `CompleteReplacementAsync` re-evaluates authority and activates through the owner transaction. Provider progress or changed parent state rejects an old choice. Old provider work may continue physically; its eventual output cannot satisfy the replacement revision. No Retry or condition-bound Cancel action is offered. Existing workflow-wide cancellation retains its independent current-scope authority semantics.

`ResumePreparedReplacementAsync` reconciles proposal-created-before-receipt linkage. Completion reconciles an exact already committed proposal if the host died before its receipt update. A different pending proposal or a different candidate cannot be adopted. Durable receipts and authority evidence allow review of why extra read/report computation was or was not permitted. Recovery does not imply arbitrary external duplication safety or physical operation termination.

Host tables are experimental: `supervisor_revision_intents`, `supervisor_pending_discussions`, `supervisor_operator_checkpoints`, `supervisor_proposal_contexts` and `adaptive_delegation_recovery_decisions`. Existing M1 tables and state machine retain ownership. Initialization is additive; dismissal adds a nullable host column to existing M2 stores. Retain owner archives/outbox for recovery. Do not use these host tables as a public stable schema or permit untrusted callers to edit them.

Compatibility remains preview/0.x: M2 changes only non-packable Marang host composition. The pinned M1 NuGet producers, stable 1.0 foundations and existing consumer contracts are unchanged. No package publication or 1.0 graduation is needed. Any future incompatible continuity-schema change requires an explicit migration and restart/consumer conformance probes.
