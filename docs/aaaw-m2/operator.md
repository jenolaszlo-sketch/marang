# Returning to an adaptive repository workflow

The experimental console runs from the repository's qualification executable. Use an existing M2 evidence directory with `--phase supervisor-view --dir <directory> --interactive true`. Omit the interactive flag to print only the current catch-up view. The fixture identifies `qualified-operator`; a real host must supply authenticated identities and scope policies.

`now` shows the current goal, revision, execution/result authority, pending decisions and provider conditions. `changes` shows meaningful changes since the operator's checkpoint. `results` separates current accepted results from superseded results. `blocked` and `decisions` explain what needs attention. `timeline` lists recent transitions; `revision revision-3` explains any retained transition, including preserved/reused/fenced/replaced work. These reads use durable owner state, not a conversation replay.

`proposal` reviews the exact pending candidate and retains a local review token. `approve`, `continue` and `reject` require that token to still match the pending immutable proposal. Approval uses current Hufu authority; continue reloads the exact durable receipt and checks authority again before atomic activation. This console activates an admitted revision; the enclosing execution host remains responsible for dispatch. It does not install new planners or reinterpret prose as executable commands.

`discuss <question>` saves concise pending context without changing execution. `dismiss discussion` closes that context, including a stale discussion, without applying its choice. Begin a fresh discussion after state/evidence changes. `acknowledge` records the current revision and watermark for catch-up deltas. `cancel` uses the existing current-authority cancellation seam and never implies physical cancellation of external effects.

For a genuinely unresolved provider-start fixture, `--phase supervisor-delegation --dir <directory> --interactive true` exposes wait and replace. Replace produces a finite local read/report recovery proposal and separately requests approval of that exact candidate. The old operation may still exist: activation fences its result authority. The fixture does not offer retry, compensate effects, or accept unknown results. Workflow-wide cancellation is a separate current-scope command, not a choice bound to an older recovery condition. Calling this phase against a store that lacks the actual killed-provider evidence is rejected.

Repository qualification starts with `--phase continuity --dir <new directory> --barrier unused`, then a fresh process uses `--phase continuity-resume` with the same directory. It retains one R1→R2→R3→R4 workflow, actual Fuwen/Zhinu work, immutable repository snapshots, and a single inventory invocation. Scenario A changes report/review requirements; B introduces Linux/Windows declared-target assessment branches and .NET target evidence; C revises a conclusion using an actual unknown-provider failure probe. Target assessments describe repository declarations and qualification gaps, not Linux/Windows builds.

Reproduce build, formatting and full M1/M2 consumer checks with `eng/qualify-aaaw-m2.ps1`. Default sibling producer paths match the isolated local worktrees; for CI or another checkout pass the exact clean M1 producer paths. `-ReuseQualifiedPackages` uses an already built local feed; its package hashes and source lock must match M1 evidence. No publication is part of this milestone.
