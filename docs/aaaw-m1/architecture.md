# M1 adaptive control loop

The qualification scenario reviews the repository's actual README and package references, creates several independent read/report branches, then receives a user change from JSON to Markdown with restart limitations. The planner/replanner are deterministic fixtures. Execution still passes through genuine Fuwen compilation/admission, the Fuwen–Zhinu execution adapter, Zhinu durable steps, the public Qingniao delegation runtime, current Hufu/Cedar evaluation and Hongxian's session ledger.

Plan is a verified canonical Fuwen definition. Revision is immutable Fuwen lineage plus a runtime manifest. Execution is a collection of independently leased Zhinu runs selected by that manifest. These objects are retained separately. A revision-specific step identity differs from its logical identity; execution, delegation, attempt and provider task identities remain distinct.

The finite authoring profile supports 2–16 independent read/report branches and at most one join of all branches. It rejects other graphs. The provider ports never interpret prose as permission to execute arbitrary commands or alter the repository. Qualification writes only its own evidence directory. A live model may propose work specifications, but it cannot install a runtime manifest or approve it.

The supervisor validates Fuwen bytes, schema, identities, graph, input binding, branch equivalence and host authority profile. It calculates a conservative change set. Contract, inputs, provenance, authority or dependency changes invalidate work and transitive dependents. Completed reuse requires explicit acceptance and matching evidence. Identical names are insufficient.

The operator view explains preserved, historical and replacement work using titles. Approve, Reject, Cancel and Discuss are authenticated host methods. Approval is exact to workflow, parent revision, parent authoritative state and proposal digest. Another change obsoletes the pending proposal. Execution progress—including Qingniao's projected durable witness—makes the proposal stale rather than silently merging it.

Use `docs/aaaw-m1/revision-contract.md` for transaction details and `docs/aaaw-m1/delegation-recovery.md` for recovery limits. ADR 0016 records the ownership decision. No stable package is being graduated or published by this milestone.
